## ISSUE 9 — Progress Stuck at 10%

### Problem

Frontend always showed:

```text
10%
↓
Directly 100%
```

### Root Cause

Backend internally updated progress BUT:

* Job registry never synced live progress
* Frontend polling only saw stale values

### Major Architectural Discovery

```text
ConversionJob.progress updated internally
BUT
JobRegistry never updated during processing
```

### Final Resolution

Implemented:

* Progress callback architecture
* Live registry synchronization
* Real-time frontend polling

### Final Working System

```text
ProgressTracker.update()
↓
progress_callback(job)
↓
JobRegistry.update_job()
↓
Frontend polling detects updates
↓
UI progress updates live
```

---

## ISSUE 10 — Recursive Callback Bug

### Problem

`manager.process_job()` accidentally called INSIDE callback.

### Result

Infinite recursive callback loop.

### Resolution

Moved:

```python
result = manager.process_job(...)
```

outside callback function.

# 16. Real Backend Processing Flow

## Step 1 — Upload Request

Flutter sends:

```text
POST /upload
```

with:

* image files
* optimization settings
* quality values
* resize settings
* target size settings

---

## Step 2 — Backend Creates Batch Job

Inside:

```python
upload_images()
```

backend:

* generates batch job ID
* stores job in JobRegistry
* saves uploaded files
* creates ConversionJob objects

---

## Step 3 — Background Thread Starts

Backend starts:

```python
threading.Thread(...)
```

This prevents frontend blocking.

Frontend immediately receives:

```json
{
  "job_id": "..."
}
```

---

## Step 4 — Flutter Polling Begins

Frontend repeatedly calls:

```text
GET /job/{job_id}
```

using:

```dart
while (!completed)
```

polling loop.

Polling interval:

```dart
300 milliseconds
```

---

## Step 5 — ConversionManager Processes Image

Inside:

```python
manager.process_job()
```

system performs:

1. Loading
2. Preparing
3. Conversion
4. Result analysis
5. Heatmap generation
6. Comparison generation
7. Completion

---

## Step 6 — ProgressTracker Updates Progress

System internally updates:

```python
job.progress
job.current_stage
```

through:

```python
ProgressTracker.update(...)
```

---

## Step 7 — Live Progress Callback

Major architectural improvement added:

```python
progress_callback(job)
```

This callback synchronizes:

```text
ConversionJob state
↓
JobRegistry state
↓
Frontend polling responses
```

This solved the major “10% stuck” issue.

---

## Step 8 — Frontend Receives Live Updates

Flutter receives:

```json
{
  "progress": 50,
  "current_stage": "converting"

```

Frontend then updates:

```dart
setState(...)
```

which rebuilds:

* progress bar
* percentage text
* stage label

in real time.

## Step 9 — Results Returned

backend returns:

* optimized file path

* heatmap path
* comparison image path
* resolution

# 17. Biggest Engineering Problem Solved

## The “10% Progress Bug”

### Original Problem

Frontend progress remained:

```text
10%
```

until completion.

Then instantly jumped to:

```text
100%
```

---

## Root Cause

Backend updated progress internally BUT:

```text
ConversionJob.progress updated
BUT
JobRegistry never updated live
```

Frontend polling only read JobRegistry.

Therefore frontend always saw stale progress.

---

## Final Engineering Solution

A callback-based synchronization system was introduced.

### Architecture

```text
ProgressTracker.update()
↓
progress_callback(job)
↓
JobRegistry.update_job()
↓
Frontend polling
↓
setState()
↓
Live progress UI
```

This converted MediaFlux from:

```text
fake static progress
```

into:

```text
real-time synchronized progress tracking
```
